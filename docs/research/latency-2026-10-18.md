# Lyrics latency measured through Navidrome

Measured on 2026-10-18 on macOS arm64 using a locally built Navidrome server
and the packaged Go WASI plugin. These are HTTP response times for
`getLyricsBySongId?enhanced=true`, including WASM startup, provider work,
parsing, serialization, and reading the response. They do not measure browser
paint or karaoke animation.

## Results

Each row contains five requests, one for each track. Values are milliseconds.
The baseline is plugin commit `97bf214`; the candidate includes the changes
in this PR. Both ran against the same Navidrome build, based on `8cb41929`
with this task's host and UI fixes.

| Scenario | Baseline median | Candidate median | Candidate range | Immediate lyric hits |
|---|---:|---:|---:|---:|
| First provider deliberately stalled | 6848 | 1578 | 1471–1639 | 3/5 in both builds |
| All provider connections deliberately stalled | 18046 | 2036 | 2029–2040 | 0/5 in both builds |
| Live providers, cold plugin cache | not measured | 120 | 113–395 | 5/5 |
| Immediate replay, warm plugin cache | not measured | 60 | 49–98 | 5/5 |
| Cached alternatives after background discovery | not measured | 151 | 120–202 | 5/5, with 5–6 variants each |

The failed first provider costs at most its 750 ms foreground slot rather
than a six-second request timeout. The total foreground network budget is
two seconds. The all-stalled response also includes about 30–40 ms of host
and plugin overhead. A faster error response does not imply lyrics were found.

## A host-clock issue found by measurement

This Navidrome build configures WASI with `WithSysWalltime` but without
`WithSysNanotime`. Go's `time.Now()` therefore carries real wall time and a
synthetic monotonic reading. Subtracting these values counted almost none of
the time spent in blocking host HTTP calls. The old eight-second lookup
budget actually allowed three six-second requests, taking 18 seconds.

The plugin now strips the monotonic component with `time.Now().Round(0)` at
its clock boundary. Source deadlines, the total lookup deadline, background
sweep budgets, and diagnostic elapsed times then use the real wall clock on
these hosts. This also works on hosts with a real monotonic clock.

## Method and reproduction

1. Build the plugin with `mise run check`. Build Navidrome with
   `go build -tags netgo,sqlite_fts5` after building its UI.
2. Start Navidrome on loopback with a new data directory, plugins enabled,
   `LyricsPriority = "better-lyrics"`, default source order, and no provider
   credentials. Enable the plugin and restart the server. Verify its load
   succeeded before measuring.
3. Scan silent MP3 fixtures tagged as Bohemian Rhapsody / Queen / 354 s,
   Bad Guy / Billie Eilish / 194 s, Shape of You / Ed Sheeran / 234 s,
   Blinding Lights / The Weeknd / 200 s, and Hello / Adele / 295 s. The
   plugin receives their metadata; there are no local lyric sidecars or tags.
4. Time authenticated enhanced Subsonic requests with a monotonic client
   clock, ending after the JSON response is read. Request each song once
   cold and once immediately afterwards. After 45 seconds, request each
   song again to inspect cached alternatives. Background discovery stays
   enabled throughout.
5. For fault scenarios, start each build with a separate fresh plugin store
   and route its HTTP traffic through a loopback CONNECT proxy. For the
   first-provider case, stall TLS after CONNECT to `lyrics-api.boidu.dev`
   and tunnel other hosts unchanged. For the all-stalled case, stall every
   CONNECT. Keep connections open until the caller times out. Only these
   temporary fixture packages add `127.0.0.1` to `requiredHosts` to permit
   the local proxy. Their WASM is unchanged; the shipping manifest does
   not allow loopback. Check proxy events to confirm faults were applied.

[Raw measurements](latency-results-2026-10-18.json) contain every included
sample and the candidate WASM SHA-256. They contain no credentials or lyric
text. Preliminary runs with an unloaded plugin or a blocked proxy are excluded.

These are small sequential cohorts, not percentile estimates or load tests.
Cold means a fresh local plugin cache; public provider caches and upstream
network conditions are uncontrolled. Simultaneous client lookups can still
wait for Navidrome's concurrency limit. Background sweeps share one worker,
so queued alternatives may arrive after a minute. The matching UI changes
check every five visible seconds initially, then every 30 visible seconds
while the song remains open. Browser timing and live playback remain separate
verification tasks.
